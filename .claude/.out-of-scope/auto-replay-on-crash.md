# 中斷後自動重播／自動重啟

- **提案日期**：2026-09-23
- **拒絕日期**：2026-09-23
- **狀態**：條件性拒絕

## 概念

agent 中斷後，由系統自動把它叫回來、從斷點重播沒做完的步驟，不經過人。
Temporal 的 durable execution、LangGraph 的 checkpointer 重播是這個形狀。

## 為什麼不做

1. **重播的前提不成立。** Temporal／LangGraph 能重播，是因為工作流程程式碼是確定性的，
   有副作用的部分被隔離成可重試的 activity。agent 的每一步是一次模型決策，同樣的輸入不保證同樣的動作；
   重播有副作用的工具呼叫，就是重複 push、重複開 PR、重複發訊息。
2. **自動重啟就是無人監督的長時間自主執行**——已在 `general-capability-rejected.md` 第一條否決，
   理由相同：與「人的決策是全域鎖」衝突。
3. **自動還原工作樹會毀掉別人的工作。** 斷點之後被改過的檔案可能是使用者的；
   把工作樹倒回斷點違反 `core-rules` 第 3 條。斷點的物件留在 git 物件庫裡，需要時手動取回
   （`git checkout <tree> -- <path>`），不自動。

## 採用的替代

`tools/checkpoint.py` ＋ `hooks/checkpoint.sh` ＋ `skills/se-resume`：斷點自動寫，
續跑由模型做，但先拿到現實——哪些變更是自己的、哪些驗證失效、哪些副作用已經發生。

## 什麼情況下該重新考慮

- 某一類長任務的每一步都能寫成**確定性、可重入**的指令（例如資料批次處理），而且人已經拍板過全部決策——
  那一類可以做成腳本自己的續跑（見 `se-resume`「長時間腳本自己的斷點」），不需要 agent 參與。
- 自動重啟：同 `general-capability-rejected.md` 第一條的重新考慮條件。
