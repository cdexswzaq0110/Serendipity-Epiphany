# 通用能力的三條被否決路徑

- **提案日期**：2026-09-22
- **拒絕日期**：2026-09-22
- **狀態**：條件性拒絕

## 概念

目標是讓這套配置具備通用人工智慧定義裡的四種性質：自主自控、自我理解、學習新技能、
解決沒教過的情境。實作時有三條看起來最直接的路，全部否決。採用的是另外一條：
**通用性來自學習的遷移，不是能力的堆疊。**

## 否決的三條與理由

### 一、無人監督的長時間自主執行

**概念**：一個常駐的迴圈 daemon，給它目標就自己跑到完成，不需要每輪人工確認。
oh-my-claudecode 的 `/autopilot`、`/autoresearch` 是這個形狀。

**為什麼不做**：與「人的決策是全域鎖」直接衝突。這套配置的主張是需要人拍板的決策
**必須**交給人，一次一個。一個不停下來的迴圈，要嘛替人做了決策，要嘛卡在第一個決策點——
兩種都違反那條信念。

**採用的替代**：`guard-done.sh`。它只做「自控」那一半——**不准留下壞掉的狀態就走**，
而且只強制繼續一次。它不替人決定要做什麼，只阻止做到一半就停。

### 二、不經驗證直接生成並載入 skill

**概念**：遇到新任務就自動寫一個 skill，放進 `skills/` 立刻生效。Hermes 的動態 Skill 生成
是這個形狀。

**為什麼不做**：一份外部的自進化專案分級把這條路判成**半成品**——外掛知識庫、無驗證閉環。
一個從單次經驗寫出來的做法直接進路由，就會在沒人察覺的情況下開始影響不相關的任務。

**採用的替代**：`skill-candidates/` ＋ `promote_skill.py`。候選不會自動載入；
要升級，必須實際用過（`validated`）、且有 3 條獨立來源的觸發案例——也就是一個做法要在
真實工作裡**重複出現至少三次**。

### 三、改變模型本身（微調、RL 訓練閉環）

**概念**：用成功軌跡去訓練模型，讓模型本身變強。Hermes 的 RL 路徑（Opus 當老師 → 合成軌跡
→ GRPO → 蒸餾到小模型）是這個形狀。

**為什麼不做**：這是配置層，**結構上做不到**——它只能改模型讀到什麼，不能改模型是什麼。
而且那份外部分級同樣把這條判成半成品：離線、人工驅動、不是「用著變聰明」。

## 先例

採用的那條路（遷移）有本地證據：2026-09-22 盤點時，Serendipity 7 則 lesson、churn-guard
2 則，**互相引用 0 次**；9 則的 `hits` 總和 0、升級 0 則。每個專案都在從零開始學。

## 什麼情況下該重新考慮

- **第一條**：若出現一類任務，**在人已經明確拍板過所有決策的前提下**，仍反覆因為需要人工
  逐輪確認而失敗——那時可以考慮一個有明確停止條件、有預算上限的自主段落。
- **第二條**：永久拒絕。「不經驗證就載入」與這套配置的證據紀律無法相容。
- **第三條**：若這套配置不再是純配置層（例如開始附帶可訓練的元件），重新評估。
