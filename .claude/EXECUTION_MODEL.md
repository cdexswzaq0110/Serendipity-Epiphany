# 執行模型（Execution Model）

這套 harness 的任務切分、派發與同步，全部用**作業系統併發模型**命名。理由不是好聽：Ticket 依賴、context 邊界、檔案寫入衝突、外部資源配額，本來就是排程與同步問題，借用既有語彙讓判斷有現成的直覺可用——**你已經知道兩個 thread 同時寫同一塊記憶體會出事。**

## 元件對應

| Harness 元件 | 執行模型對應 | 意義 |
|---|---|---|
| `rules/` | **Kernel** | 常駐、每個 Process 與 Thread 都繼承，不可停用 |
| `skills/` | **Coroutine 庫** | 同一個 context 內 yield 進去、跑完 yield 回來。無隔離、無平行 |
| `agents/` | **Thread／Process 模板** | 建立時就決定隔離等級、工具權限與回收方式 |
| Task／新 session | **Process** | 獨立 context，不共享記憶體 |
| Subagent | **Thread** | 獨立 context 視窗，共享工作樹 |
| 交接文字（handoff） | **IPC 訊息** | Process 之間唯一合法的傳值方式，必須可序列化 |
| `CONTEXT.md` | **共享記憶體區段** | 全體共用的命名與定義；改它等於改所有人的假設 |
| `docs/lessons/` | **持久化儲存** | 跨 Process 存活，Process 死了它還在 |
| Context window | **記憶體** | 有上限，會 OOM |
| Compact | **Swap** | 換出去再換回來會失真。能開新 Process 就不要 swap |

## 四種派發單位

| 單位 | 隔離 | 平行 | 成本 | 什麼時候用 |
|---|---|---|---|---|
| **Coroutine** | 無（同 context） | 否 | 極低 | 需要一套**方法**，不需要隔離。載入 skill 就是 |
| **Thread** | 獨立 context 視窗，共享工作樹 | 是 | 低 | 唯讀 fan-out：搜尋、審查、第二意見、蒐證 |
| **Process** | 完整（獨立 context、獨立歷史） | 是 | 高 | 一個垂直切片、一張重 Ticket、規劃→實作的邊界 |
| **Connection** | 外部資源 | 受配額限制 | 依資源 | CLI、MCP server、瀏覽器 session、DB、API 配額 |

### 判斷順序

```
需要隔離嗎？
├─ 不需要 ──────────────────────── Coroutine（載 skill，繼續做）
└─ 需要
   ├─ 只讀，不寫工作樹 ──────────── Thread
   └─ 要寫工作樹或要換乾淨 context ─ Process
```

**預設是 Coroutine。** Thread 與 Process 都有啟動成本（重新建立 context、重新讀檔），只有在隔離真的買到東西時才付。

## Pool

Pool 的意義是**有上限、可回收、不洩漏**。

### Thread Pool

一批同時派出的唯讀 Subagent。

- 適用：廣度搜尋、多軸 Review、多來源查證、平行蒐證。
- 上限：平台可用並行數。**用滿，不自行保守限制。**
- 回收：每個 Thread 回報結構化結果後即結束，不留狀態。
- 禁止：Thread 之間互相讀對方的結論（首輪必須獨立，否則兩軸 Review 的獨立性失效）。

### Process Pool

一批同時跑的獨立 Task，各自負責一張 Ticket。

- 適用：依賴不相交、寫入範圍不重疊的垂直切片。
- 上限：實際能安全隔離的寫入範圍數量，不是「你想開幾個」。
- 回收：Process 結束時必須釋放它持有的所有寫入鎖，並更新 Ready Queue。
- 禁止：兩個 Process 同時對同一分支做 git 寫操作。

### Connection Pool

外部資源不是無限的，取得後必須歸還。

| 資源 | 配額表現 | 洩漏的樣子 |
|---|---|---|
| AI CLI（Claude／Codex／其他） | 帳號並行數、rate limit | 一堆殭屍 session |
| MCP server | 連線數、啟動成本 | 每次任務重啟一次 |
| 瀏覽器 session | 登入態、分頁數 | 開了不關，記憶體漲 |
| DB／外部 API | 連線上限、每分鐘配額 | 429 之後整條流程卡住 |
| GPU／本機重運算 | 一次一個 | 兩個任務搶同一張卡 |

規則：**先探測再使用**（不只看命令存不存在，要真的跑得起來）、**取得時記錄實際用到的是哪一個後端**、**失敗時降級到備選並說明**、**結束時歸還**。

每種能力維護一份「首選 ▸ 備選」有序清單；換接入方式 = 調整清單順序，不是重寫流程。

## 同步原語

| 原語 | 在這裡是什麼 | 違反的後果 |
|---|---|---|
| **Ready Queue** | `Blocked by` 已全數完成的 Ticket 集合 | 沒重算就派工 → 做到一半發現前置沒好 |
| **Mutex（寫入鎖）** | 同一檔案／模組／Schema／Migration／Lockfile／同分支 git 寫入 | 覆蓋彼此的變更 |
| **Semaphore** | 平行上限：平台並行數、API rate limit、GPU 張數 | 429、逾時、被限流 |
| **Critical Section** | 不可逆操作：`push --force`、`reset --hard`、migration、部署、刪資料 | 沒有回頭路 |
| **Barrier** | 所有 Ticket 完成後才做的總驗收 | 逐張宣稱完成，整體其實不成立 |
| **Fork / Join** | 派工 → 收斂結論 | 只 fork 不 join：結果散落在各 Thread 的回報裡沒人整合 |
| **Race Condition** | 兩個 session 同時推進同一個 ref | 重複 cherry-pick、分支 tip 對不上 |
| **Deadlock** | 兩張 Ticket 互相等對方的產物 | 整條流程停住 → 拆依賴或合併成一張 |
| **Starvation** | 某張票永遠排不到（總是被判定為衝突） | 拆小它的寫入範圍 |
| **GIL** | **使用者本人**。需要人拍板的決策全域序列化 | 同時丟三個決策給人，等於三個都卡住 |

### GIL 這條要特別記

人的決策是全域鎖。**同一時間只該有一個問題在等人回答。**

所以：能自己查的事實自己查（環境、程式碼、文件、工具），只把**決策**交給人；一次問一個決策，附推薦答案與代價；發現多個缺口時，只問「猜錯要重做」的那些，其餘宣告假設往下走。

## 記憶體管理

| 概念 | 規則 |
|---|---|
| **水位線 ~120k** | 規劃還沒完成就逼近它 → 寫進計畫檔、開新 Process。不要硬撐 |
| **OOM** | Context 爆掉。表現是模型開始忘記前面確認過的事 |
| **Swap（compact）** | 會失真。跨 Process 靠**落地產出**接續（計畫檔、測試、commit），不靠對話摘要 |
| **不可中斷區** | 探索 → 規劃 → 切片，全程同一個 Process。中途 swap，後面每片都建立在摘要過的推導上 |
| **必須中斷區** | 切片之間。上一片的實作細節對下一片是雜訊 |

## 切片 = Process 的大小

一張 Ticket 是一個 Process 的工作量。四個判準：

1. **完整** — 交付一個端到端可觀察的結果，不是只完成單一技術層。
2. **可獨立驗證** — 有能直接觀察或重現的驗收條件。「完成實作」不是驗收條件。
3. **塞得進一個新 Process** — 從零 context 開始，讀完該讀的還做得完。
4. **接縫已定** — 測試要放哪已經確認過（`se-lazy-ladder` 與接縫規則）。

塞不進一個 Process = 切太粗，回去重切。

## 依賴最小化

拆票時**最大化初始 Ready Tickets**。不得因為以下理由建立 `Blocked by`：

- Ticket 編號或建議順序
- 共用唯讀程式碼
- 尚未查證的「可能會衝突」

只有**後一張確實需要前一張的產物或決策**時，才是真依賴。

寫入範圍衝突不是依賴，是**鎖**——標明衝突範圍，讓排程器序列化它們，而不是把它們串成鏈。

## 升級與降級

| 情況 | 動作 |
|---|---|
| Process 回報能力不足（有可重現證據） | 換更強配置的新 Process 接手同一 Ticket 與既有證據 |
| 已是最強配置仍受阻 | 依實際阻擋繼續查證，或交給 GIL（問人） |
| Thread 拿不到必要資料 | 回報阻擋，不猜測性擴大範圍 |
| Connection 首選失效 | 降級到備選，**明說換了哪一個**，不靜默切換 |

每次派發都記錄：派發單位、實際 Agent／CLI、實際模型、實際推理強度、判定依據。取不到就如實記 `unknown`，**不得把預期值當成執行證據**。
