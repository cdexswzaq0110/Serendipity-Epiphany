# 淨化：一則 Lesson 被發現是錯的

> `se-epiphany` 模式四的完整程序。**只在確認某則 Lesson 的內容本身有問題時走這裡**，
> 一般的過期走模式三的「標失效」。

## 先分清楚：過期 ≠ 污染

| | 過期（stale） | **污染（polluted）** |
|---|---|---|
| 發生什麼 | 世界變了，這則不再適用 | **它從一開始就是錯的**，或內容來自沒驗證過的來源 |
| 怎麼發現 | `anchors` 指的檔案被刪或大改；`失效條件` 觸發 | 依它做的決策出錯，回頭才發現前提是假的 |
| 危險程度 | 低。它只是不再有用 | **高。它已經改變過決策，而且當時沒人察覺** |
| 處置 | 標 `stale`，重驗或封存 | **走下面三步** |

**為什麼污染比一般 bug 危險**：快取壞掉會拋 Error，執行會停下來。
髒記憶不會停——Agent 會拿著錯的前提繼續自主決策，而且**不自知**。
壞掉的東西會叫，髒掉的東西不會。

## 三步

### 第 1 步：溯源

**先確定它影響了什麼，再動任何東西。**

```bash
# 這則寫進來之後的所有 commit
git log --since="<lesson 的 date>" --oneline

# 有誰引用過它（其他 lesson、rules、ABLATION、commit message）
grep -rn "L00XX\|<lesson 檔名>" --include="*.md" .
git log --all --grep="L00XX" --oneline
```

`hits` 只說被召回幾次，**不說用在哪**。所以溯源靠的是 commit 歷史與交叉引用，
不是 frontmatter。這是目前的限制，不要假裝 `hits` 能回答這個問題。

盤出三件事：**哪些 commit 依它而做**、**哪些其他 Lesson 引用它**、
**它有沒有升級成常駐規則或 skill 內容**。

### 第 2 步：回滾與補償

分兩類處理，判準是**可不可逆**：

| 類型 | 做法 |
|---|---|
| 可逆（本地 commit、未推送的分支、檔案內容） | `git revert` 那些 commit，或直接改回來 |
| **不可逆**（已推送、已合併、已發給別人、已刪除的東西） | **不要嘗試抹掉。** 建一個補償動作：加一則更正、發一次說明、補一個相反的變更 |

不可逆的部分**必須留下痕跡**。假裝它沒發生過，就是製造第二次污染——
下一個人會讀到一段看起來完整、其實中間被挖掉的歷史。

### 第 3 步：認知重校

1. **原 Lesson 標 `outcome: corrected`，內容保留不刪。**
   錯誤假設本身就是內容——刪掉它，下次還會用同樣的方式錯一遍。
   在文末加一段「## 為什麼這則是錯的」，寫清楚錯在哪、什麼時候發現的。
2. **寫一則新的**，`supersedes` 指向它。新那則要回答：**當初為什麼看起來是對的**。
3. **如果它已經升級成常駐規則**：走模式三的「降級」，並在
   [`ABLATION.md`](../../../ABLATION.md) 登記——那條規則的失敗證據欄現在是假的，
   必須改成這次的發現。
4. **如果它影響過的判斷還沒重做**：那些判斷全部標成未驗證，重跑。
   不要因為「看起來結果還可以」就留著——結果對不代表推理對。

## 為什麼不做自動化溯源

有一個看起來很值得做的版本：在 frontmatter 加 `used_in:`，每次召回就記一筆。

**不做，理由是它會爛。** 那個欄位要靠每次召回時手動追加，漏一次就不完整，
而一份不完整的溯源紀錄比沒有更危險——它讓你以為盤過了。

git 歷史是唯一不會漏的紀錄。溯源就用它。

## 完成條件

- 影響範圍已盤出（commit、交叉引用、是否已升級）
- 可逆的已回滾，不可逆的已建補償動作**且留下痕跡**
- 原 Lesson 標 `corrected` 且內容保留，新 Lesson 已寫且 `supersedes` 指向它
- 若曾升級成常駐規則，ABLATION 的失敗證據欄已更正
