# 驗證面對照

Phase 4 說「驗證必須碰到交付物本身」，Phase 6 說「有可操作介面的，實際開起來走一次」。這份表回答**那句話在各種交付物上具體長什麼樣**。

## 對照表

| 交付物 | 碰到它 | 不算碰到 |
|---|---|---|
| Web 介面 | 開瀏覽器走一次主要流程；要自動化用 Playwright | 讀 component 原始碼、跑 render 測試 |
| Mobile | 真的跑 Simulator／實機；要自動化用 Maestro 之類的 UI driver | 只跑單元測試、只看 build 成功 |
| HTTP API | 真的送 request，讀狀態碼與 body | 讀 handler 原始碼、只跑 mock 掉傳輸層的測試 |
| CLI | 真的執行，讀 stdout／stderr 與**退出碼** | 讀 argparse 定義 |
| 資料庫變更 | 真的跑一次 migrate，再跑一次 rollback | 讀 migration 檔說「看起來對」 |
| 排程／背景工作 | 觸發一次，讀它實際寫出的副作用 | 確認函式有被註冊 |
| 函式庫／純邏輯 | 跑測試，而且確認**那個測試會為這個行為變紅** | 測試通過但拿掉實作也會過（見 `se-two-axis-review` 的 Test That Cannot Fail） |

**單元測試是證據，不是驗收。** 它證明某段邏輯成立，不證明使用者拿得到那個結果。兩者都要，順序是先驗收再看測試。

## 留證

驗收的產出要能被**第二個人重新確認**，所以留下來的東西要是別人不用重跑就看得懂的：

| 交付物 | 留什麼 |
|---|---|
| 有畫面的 | screenshot（含關鍵狀態，不只 happy path 的最後一張） |
| 有流程的 | trace／錄影，或逐步的指令與輸出 |
| 純指令的 | 完整指令 ＋ 輸出 ＋ 退出碼 |

寫進派發紀錄或 PROCESS_SPEC 的「執行紀錄」，配 `rules/evidence-grades.md` 的等級：

- **實際跑過、輸出貼在這裡** → `【已確認】`
- **這個介面照理說會通** → `【未驗證】`，而且**不得計入 PASS**

## 做不到的時候

環境起不來、缺憑證、沒有裝置——**直說做不到，不宣稱通過**（Phase 6 已規定）。

回報格式：實際阻擋是什麼、目前拿得到的最強證據是什麼、以及**這個 Process 的狀態是 `BLOCKED` 而不是 `PASS`**。用一個較弱的替代驗證換一個綠燈，是把 gate 換成裝飾。
