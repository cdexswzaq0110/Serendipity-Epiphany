# 記憶層是配置層，所以外部內容進去要有邊界，不能只靠當下的判斷

## 觸發情境

有東西要寫進 `docs/lessons/`、`CONTEXT.md` 或任何「以後會被自動召回」的地方，
而它的內容不完全來自你自己的觀察。

## 領悟

**長期記憶在 Agent 系統裡不是資料，是配置。** 一則 Lesson 被召回之後會改變後續每一次
決策，效果等同於改了一行常駐規則——差別只在它是動態載入的。

所以「記憶被寫壞」跟「快取被寫壞」是兩種東西：

| | 壞快取 | **髒記憶** |
|---|---|---|
| 症狀 | 拋 Error，執行中斷 | **沒有症狀。** 拿著錯的前提繼續自主決策 |
| 察覺 | 立刻 | 可能永遠不會 |
| 修法 | 清空、重啟 | 溯源 → 回滾／補償 → 重校 |

**壞掉的東西會叫，髒掉的東西不會。**

### 本地證據：一次無 gate 的外部寫入

`cda8caa` 把一份外部的「10 個 Coding Agent tips」消化進記憶層，最後產出 L0006。
那一次處理得很好——逐條覆蓋度對照、只有 4 條進 Skill、常駐面 0 變動。

**但整個過程沒有任何機制在把關。** 它成立是因為當時的判斷正確，不是因為有東西擋著。
換一個 session、換一種心情、或那份外部清單寫得更有說服力一點，結果就可能不同。

**靠判斷的東西，遲早會在判斷不好的那一天出事。**

## 為什麼會撞到

因為 `ABLATION.md` 一直在管**數量**（常駐面不准長大、要填得出失敗證據），
但沒有人管**來源**。

而這兩件事會失聯：一則來自外部文章的說法，只要包裝成「這是我學到的教訓」，
就能一路走完升級流程進到常駐面——它過得了「有沒有寫失敗證據」這一關，
因為那一欄可以照抄別人的失敗。

## 下次怎麼做

1. **每則 Lesson 標 `source`**：`self-observed` / `user-stated` / `external`。
   判準是**證據**來自哪裡，不是**題目**來自哪裡。對外部清單做覆蓋度對照、自己得出
   結論，那是 `self-observed`；照抄別人的建議，那是 `external`。
2. **`external` 不得升級成常駐規則。** 外部說法沒有本地失敗證據。要進常駐面，
   得先自己撞到一次——那時它就變成新的 `self-observed` 了。
3. **這條寫成 hook，不要寫成散文。** `check-memory.sh` 在 `git commit` 前擋，
   模型配不配合都會執行。判定條件寫得成 shell，就不該只是一段提醒。
4. **溯源用 git 歷史，不要另建欄位。** 曾經想加 `used_in:` 記錄每次召回，
   但那要靠手動追加，漏一次就不完整——**一份不完整的溯源紀錄比沒有更危險**，
   它讓你以為盤過了。

## 失效條件

- 若 `docs/lessons/` 改由外部系統託管（向量庫、知識圖譜），`check-memory.sh` 的
  frontmatter 檢查失效，准入控制要改在寫入介面。
- 若某天真的出現「外部來源的說法在本地也撞到了」，那則會從 `external` 變成
  `self-observed` 的新一則——本則的第 2 點要補充說明兩者怎麼銜接。
- 這則的**框架**（記憶污染 vs 一般 bug、三步淨化）來自一份外部素材；
  若那個框架被更好的取代，`references/purge.md` 要重寫，但第 1–3 點的本地證據不受影響。

## 尚未驗證

**沒做過 leave-one-out。** 依 `se-epiphany` 的四關，它過了 SCAN（`cda8caa` 是具體實例）
與 MUTATE（泛化成「任何會被自動讀取的儲存層」），**沒過 VALIDATE**——沒有證據說
「有這條 hook 會減少污染」，因為本地還沒發生過真正的污染事件。

所以它留在帳本，機制放在 hook 與 skill，**常駐面 0 行**。`validated` 空著就是這個意思。
