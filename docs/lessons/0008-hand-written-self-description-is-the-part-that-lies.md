# 自我描述裡手寫的那一段，就是會說謊的那一段

## 觸發情境

要讓一個系統描述自己——能力清單、README 的「支援什麼」、自我模型、健康檢查報告。
特別是其中一部分可以自動生成、另一部分「只能手寫」的時候。

## 領悟

**`capabilities.py` 的設計原則是「從原始碼生成，所以不會說謊」。**
skill 清單讀 frontmatter、hook 讀 settings.json、已知缺口讀 ABLATION.md、
驗證狀態讀 eval 覆蓋率——全部是生成的。

**只有一段是手寫的**：「結構上做不到的事」，因為那些東西不會從原始碼長出來。
其中一條寫著：

> 無人監督的長時間自主執行——刻意不做，見 DESIGN_RATIONALE

**DESIGN_RATIONALE 根本沒寫這條。** 【已確認：2026-09-22 讀 `docs/DESIGN_RATIONALE.md` 的「刻意不做的事」，九列裡沒有】

自我模型第一次跑起來，唯一的一個錯，就出在唯一一段手寫的內容上。
生成的部分一行都沒錯。

## 為什麼會撞到

因為寫那條的時候，「這件事我們討論過、決定不做」在我腦中是已確認的——
它在對話裡、在 commit message 裡、在 PR 描述裡都出現過。
**但它不在那份被引用的文件裡。** 我把「我知道」當成了「文件寫了」。

手寫的描述漂移，不是因為寫的人粗心，是因為**寫的人知道得比文件多**。
他會很自然地寫出一個在他腦中成立、在文件裡不成立的引用。

## 下次怎麼做

1. **能生成的一律生成。** 手寫只留給真的不會從原始碼長出來的東西。
2. **手寫的部分如果引用了別的文件，引用本身要被檢查。** 「見 X」是一個可以驗證的主張——
   去 X 裡找它。這一步很便宜，而且正是這次抓到錯的方式。
3. **自我模型第一次跑出來的時候，先讀手寫的那段。** 生成的部分錯了會很明顯（數字對不上），
   手寫的部分錯了看起來完全正常。

## 失效條件

- 若「結構上做不到的事」也改成從某份文件解析生成，本則的具體案例消失，但原則仍成立。
- 若手寫段落加上了自動的引用檢查（例如 check-router 延伸去驗「見 X」），第 2 點被機械化取代。

## 為什麼這則是錯的（2026-09-22 更正，被 [L0010](0010-a-value-nobody-cross-checked-is-the-one-that-lies.md) 取代）

「生成的部分一行都沒錯」是假的。**生成的部分裡有一個數字一直是錯的**：`capabilities.py` 找全域帳本用
`[0-9]*.md`，但 `lessons.py` 寫的檔名是 `G0001-*.md`，所以永遠回報「全域 0 則」【已確認：修正前 0、
實際 1】。

第 3 點「生成的部分錯了會很明顯」也是假的：0 是最像真的錯誤數字。它是在 churn-guard 裡被抓到的——
同一個畫面上 `recall-lessons.sh` 說「跨專案 1 則」、`capabilities.py` 說「全域 0 則」，
兩個各自實作的計數並排出現才露餡。

錯的是分類軸。「手寫 vs 生成」不是說不說謊的分界，「**有沒有被獨立來源對照過**」才是。
手寫的引用那次被抓到，是因為我去 DESIGN_RATIONALE 對照了；生成的計數沒被抓到，是因為沒人對照。

原文保留：錯誤的分類本身就是內容。
